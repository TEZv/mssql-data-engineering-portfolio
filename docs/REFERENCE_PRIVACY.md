# Commercial references without disclosing confidential information

“References” can mean different evidence depending on the employer and contract:

- confirmation of employment dates, role and seniority from HR;
- a former manager or colleague who has agreed to confirm the candidate's contribution;
- a short recommendation letter or LinkedIn recommendation;
- an anonymized project sheet describing domain, duration, responsibility, stack and outcome;
- for formal procurement, an accepted-delivery protocol or client confirmation may be required.

Confidential information is not required for a responsible reference. A safe project sheet can say:

> European media company; reporting automation project; 2025-2026; responsible for data preparation, KPI logic, Python/SQL transformations and dashboard delivery; production data, client identifiers, revenue values and source code omitted under confidentiality obligations.

## Rules

- Ask the reference person before sharing their name, email or phone number.
- Never publish customer data, credentials, contracts, internal screenshots, private repository code or exact confidential metrics.
- Use ranges or qualitative outcomes unless exact numbers are approved for disclosure.
- Provide sensitive documents privately to the recruiter only when necessary; redact unrelated personal and commercial data.
- If the requirement is formal, ask exactly which evidence is accepted before investing time in the process.
- Independent lab projects remain labelled as labs and do not become commercial references.

## Recruiter question (Polish)

> Czy chodzi o publiczne portfolio projektowe, czy o formalne potwierdzenia od klientów/pracodawców (np. referencje, protokoły odbioru lub wykaz usług)? Ze względu na poufność mogę opisać zakres i swoją odpowiedzialność w sposób zanonimizowany oraz przedstawić dozwolone potwierdzenie prywatnie w procesie rekrutacyjnym.

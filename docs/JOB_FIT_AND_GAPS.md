# Job fit and gaps for the supplied Polish vacancies

## 1. Junior MS SQL Server Database Developer — strong near-term target

| Requirement | Evidence after this portfolio | Remaining risk |
|---|---|---|
| T-SQL procedures, functions, views | Present across all three projects | Be ready for live coding without AI/autocomplete |
| Relational design | Greenfield ERP model, constraints, keys and dimensional layer | Explain normalization versus dimensional choices |
| Testing/debugging | Executable assertions and error handling | Add a green CI link before application |
| Query optimization | Index strategy, Query Store and DMV diagnostics | Produce one measured before/after execution-plan case |
| Documentation | READMEs, evidence matrix and runbooks | None material |
| Three completed projects | Three independent lab projects | Employer may mean formal/commercial references |
| Two maintenance projects | Media mart + Reliability Lab | Employer may reject labs for a public-sector eligibility rule |
| One larger new build | Retail ERP warehouse | Runtime proof and architectural walkthrough needed |
| English | CV states upper-intermediate | Validate comfortably in an interview |
| Polish C2 | Not evidenced in the source CV | Major filter if C2 is truly mandatory |

**Assessment:** Apply once CI is green, but label the projects as independent lab work. Ask the recruiter whether public GitHub projects meet the “completed projects” eligibility criterion. The unusually specific project-count wording may be a formal public-procurement requirement, in which case portfolio evidence might not substitute for signed commercial references.

## 2. Junior Power BI / FP&A Analyst — credible now

Strengths: real data-analyst employment, Power BI, Excel, Python, reporting automation, business metrics and finance-adjacent analysis. Gaps: FP&A ownership, budgeting/forecasting and confirmed Polish level. This role fits the current CV more directly than a middle data-engineering title.

## 3. Data Engineer — ERP Technologies (mid band) — stretch target

Strong overlap: Python, SQL, business collaboration, analytical pipelines, retail/finance-flavored portfolio, data quality and CI. Terraform/Azure SQL infrastructure is now implemented and locally validated without admin rights. Material gaps remain: a captured real cloud deployment, GCP/Snowflake, SAP structures and demonstrable multi-year data-engineering delivery.

**Assessment:** Apply selectively as a transition candidate. Describe Terraform as implemented and validated, not yet deployed. The next evidence increment is one controlled Azure `plan/apply/smoke-test/destroy` run with redacted artifacts; this still does not manufacture a three-year commercial track record.

## 4. Palantir / Databricks / AML and senior ERP roles — not current targets

Palantir Foundry, PySpark/Databricks, AML, SAP Billing/CRM and Oracle Siebel/RODOD roles require product-specific, enterprise hands-on experience. A general SQL portfolio cannot credibly replace those requirements. Use them as a skill-demand signal, not as immediate application targets.

## Recommended application order

1. Junior/regular SQL Server developer and Power BI roles.
2. Junior-to-mid analytics engineer / BI engineer roles using SQL + Python + Power BI.
3. Selected mid data-engineering roles that explicitly accept project-based experience.
4. Cloud/ERP-specific roles after one deployed cloud project and one IaC artifact.

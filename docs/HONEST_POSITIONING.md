# Honest positioning for applications

## CV project section (English)

**MS SQL Server Data Engineering Portfolio — Independent Lab Projects (2026)**

- Designed and implemented three reproducible SQL Server projects covering greenfield database development, analytical data marts, and operational maintenance.
- Built a retail ERP order-to-cash warehouse with dimensional modeling, SCD Type 2 history, incremental stored procedures, audit trails, reconciliation checks, and reporting views.
- Developed a media performance mart with idempotent ingestion, late-arriving corrections, weighted-retention calculations, window-function reporting, and automated data-quality assertions.
- Created a SQL Server reliability toolkit for integrity checks, index/statistics maintenance, Query Store diagnostics, backup verification, data retention, and incident runbooks.
- Packaged the projects with synthetic fixtures, Docker-based reproducibility and CI integration tests; no proprietary data is included.

## Polish application wording

> Zrealizowałam trzy niezależne projekty laboratoryjne w MS SQL Server: greenfieldową bazę i hurtownię dla procesu order-to-cash, mart analityczny dla danych mediowych oraz zestaw procedur utrzymaniowych i diagnostycznych. Projekty są publicznie weryfikowalne w GitHubie, zawierają testy, dokumentację i syntetyczne dane. Nie przedstawiam ich jako doświadczenia komercyjnego — moje doświadczenie zawodowe pochodzi z analityki danych i automatyzacji raportowania.

## Interview answer when asked “Were these commercial projects?”

> No. They are completed independent lab projects built to demonstrate SQL Server engineering practices. My commercial background is in data analytics and reporting automation. I deliberately keep those facts separate. I can walk you through design decisions, failure modes, tests and trade-offs in the repository, and I am comfortable completing a live SQL task.

## Claims to avoid

- “Three years of SQL Server commercial experience.”
- “Three client projects” or invented client names.
- Production volume, latency or cost savings that were not measured.
- Azure, Always On, SSIS, SSAS or SSRS hands-on experience until a working artifact exists.
- Calling Terraform “deployed to Azure” while only initialization and validation have run.
- Calling a CI workflow “green” before it has actually run successfully.
- Describing the synthetic Retail ERP build as enterprise-scale or high-volume before a measured scale test exists.

## Recommended headline

`Data Analyst transitioning to SQL / Data Engineering | T-SQL, Python, Power BI | MS SQL Server portfolio`

Use `Middle Data Engineer` as the target role, not as a fabricated current title. The strongest application strategy is to combine real analytics delivery with inspectable engineering artifacts.
